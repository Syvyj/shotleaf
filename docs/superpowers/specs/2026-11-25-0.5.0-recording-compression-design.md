# Shotleaf 0.5.0 — запис екрана і швидке стискання

Дата: 2026-11-25. Статус: усі відкриті питання вирішено, чекає погодження власником.

## Навіщо

Власник переглянув Clop (платний закритий оптимізатор для Mac) і вирішив, що 0.5.0 — це відео. Типовий випадок із його слів: **короткий баг для Telegram, 20–30 секунд: виділив область і записав.** Разом із записом іде швидке стискання картинок: зараз «JPEG під N» сховано в «Зберегти як» (діалог, 3–4 кліки), а «Копіювати», перетягування і «Поділитися» завжди дають повний PNG.

Успіх: баг від натискання гарячої клавіші до ⌘V у Telegram займає кілька секунд. Скріншот потрібного розміру копіюється однією кнопкою, без діалогу.

## Цілі

1. Запис області екрана в MP4 з вікном після зупинки: перегляд, обрізання, копіювання, перетягування, збереження, GIF, «Під N МБ».
2. Стискання картинки без діалогу: окрема кнопка «Копіювати меншим», дія в буфері через ⌘K, стискання у фоні.
3. Дрібніші речі з того самого переліку (власник: «усе в 0.5.0»): зменшення картинки в редакторі клавішами, обрізання під пропорції, дії для Shortcuts.

## Не цілі

- Посилання на відео через s.syvyj.dev. Власник: «відео через посилання ми не поширюємо». Worker не змінюємо.
- WebP / AVIF / JPEG XL, PDF, аудіо, стеження за теками, ланцюжки дій, командний рядок.
- Автоматичне стискання кожної скопійованої картинки (як у Clop). Менеджер буфера не повинен тихо підмінювати скопійоване.
- Звук у записі (мікрофон, звук системи). *Моє рішення:* для бага він не потрібен, а власник не просив. Можна додати пізніше.
- Окремий режим «запис вікна». Весь екран записується, якщо виділити весь екран у тому самому інструменті.

## Антицілі (провал, навіть якщо формально працює)

- Будь-яка стороння бібліотека (правило з 0.3.0, ADR-0071) або мережевий запит, якого користувач не робив сам.
- Звичайні «Копіювати» чи перетягування, що непомітно віддають стиснуту картинку.
- Вікно знімка, що підвисає під час стискання великого довгого скріншота (так зараз з `SmallFile.jpeg` у головному потоці).
- Відео, яке Telegram на телефоні не програє.

## Обмеження

- macOS 15+, Apple silicon, Swift 6. Лише ScreenCaptureKit, AVFoundation, ImageIO, App Intents.
- Дозвіл Screen Recording уже є. Нових дозволів не просимо.
- Випуск, як і раніше, через `RELEASING.md`, Homebrew-формулу, Gitea і GitHub лише з дозволу.

## Підходи до запису (вибрано 1)

1. **`SCRecordingOutput` + постобробка AVFoundation — вибрано.** З macOS 15 ScreenCaptureKit сам пише MP4. Курсор і підсвітку кліків малює система (`showsCursor`, `showMouseClicks`), кодування апаратне. Обрізання через `AVAssetExportSession`. «Під N МБ» — перекодування через `AVAssetWriter` з бітрейтом під розмір. GIF — кадри з `AVAssetImageGenerator`, зібрані через ImageIO. Найменше коду. Компроміс: вигляд кліків і бітрейт запису вирішує Apple.
2. `SCStream` + власний `AVAssetWriter`. Повний контроль над кадрами (свої кліки, пауза), але значно більше коду і ризиків із синхронізацією та пам'яттю. Для 20–30 с бага не потрібен.
3. `AVCaptureScreenInput` — застарілий, відкинуто.

Власник вибрав 1.

## Дизайн: запис екрана

**Початок.** Нова дія гарячої клавіші `HotkeyAction.record` («Запис екрана»), за замовчуванням **⌘⇧6** (*моє рішення:* ⌘⇧1–3 зайняті). Її можна змінити в Settings › Shortcuts, як інші. Також є пункт у меню. Область вибирається наявним `RegionPicker.pickArea()`: заморожений екран, лупа, вибір вікна, весь екран, повтор останньої області. Режим прокрутки (S) для запису не має сенсу й вимикається.

**Під час запису.** Тонка рамка навколо області, яка не потрапляє у відео (вікно виключене з `SCContentFilter`). Значок у рядку меню стає кнопкою «Стоп» із таймером. Та сама гаряча клавіша зупиняє запис. Записується одна область одного дисплея (`Picked.displayID`), у рідних пікселях, до 30 кадрів на секунду.

**Формат.** MP4, H.264. *Моє рішення:* HEVC дає менший файл, але старі Android-телефони в Telegram його іноді не програють. 30 с області — приблизно 2–5 МБ.

**Після «Стоп»** відкривається вікно запису (варіант A, вибраний власником), у тому ж стилі, що вікно знімка:

```
┌──────────────────────────────────────┐
│ ▶  [ відео ]                         │
│ ├──▮━━━━━━━━━━━━━━━━━━━━━━▮──┤ 0:24  │
│ Копіювати ⏎ · Перетягнути · Зберегти │
│ GIF · Під 8 МБ ▾                     │
└──────────────────────────────────────┘
```

- **Обрізання:** два повзунки на шкалі, перегляд із програвачем AVKit. Усі дії нижче застосовуються до обрізаного фрагмента.
- **Копіювати (⏎, перша кнопка):** URL файлу MP4 у буфер. Telegram і Finder вставляють його як файл через ⌘V.
- **Перетягнути:** той самий файл (як `DragOutView` у вікні знімка).
- **Зберегти:** у теку знімків із налаштувань.
- **GIF:** робить GIF з обрізаного фрагмента, далі копіювання чи перетягування так само. *Моє рішення:* 12 кадрів на секунду, довша сторона до 960 px. Межа якості ImageIO — смуги на градієнтах, для інтерфейсу прийнятно.
- **Під N МБ ▾:** 8 / 10 / 25 МБ та «Оригінал». Бітрейт рахується з тривалості обрізаного фрагмента, за потреби зменшується розмір кадру. *Моє рішення:* оригінальний запис завжди зберігається, кожне «під N» і кожен GIF кодуються з оригіналу в **новий** файл (як «завжди з оригіналу» в Clop). Тож можна повернутися до оригіналу чи вибрати іншу межу, а вже скопійований файл не перезаписується. Після зміни обрізання результат кодується заново. Останній вибір межі запам'ятовується.

Файли запису лежать у тимчасовій теці застосунку (`TempFolder`) і, як знімки, живуть до наступного запуску (застосунок, куди вставили, може прочитати файл пізно). Закриття вікна їх **не** видаляє (*моє рішення*, за наявним правилом `TempFolder`). Записи по 2–5 МБ, тож тека за день не розростеться.

## Дизайн: швидке стискання

Спільна основа — наявний `SmallFile.jpeg(_:under:)`: найвища якість, що вміщається, а якщо ні — менша картинка. Зміни:

- **У фоні.** Виклик виноситься з головного потоку (`Task.detached`), на кнопці показується індикатор. Вікно не підвисає.
- **Межі:** 200 КБ, 500 КБ, 1 МБ, 8 МБ, 25 МБ. Останній вибір запам'ятовується в налаштуваннях (один спільний для картинок).
- **Що потрапляє в буфер** (*моє рішення*): JPEG-дані (`public.jpeg`) і URL JPEG-файлу в `TempFolder`, без PNG/TIFF. Так застосунки, що беруть файл чи JPEG, отримують саме стиснуті байти. Стиснута копія позначається як власна (`ClipboardHistory.ownType`) і в історію новим записом не потрапляє: історія зберігає картинки як PNG, тож стиснутий запис там знову став би великим. Оригінал в історії лишається.
- **Вікно знімка:** нова окрема кнопка **«Копіювати меншим ▾»** (рішення власника, варіант A). Клік копіює JPEG під останню межу, стрілка вибирає іншу межу. Ту саму кнопку можна перетягнути, і вона віддасть стиснутий файл (*моє рішення*: «стиснуте перетягування» без окремої кнопки). Звичайні «Копіювати», перетягування і «Поділитися» лишаються повним PNG. «Зберегти як › JPEG під N» лишається і отримує нові межі.
- **Буфер, ⌘K:** для картинки в списку дій з'являється «Стиснути до JPEG під N» (межа — остання вибрана, підменю для інших). Результат вставляється так само, як інші дії «Paste it…» (у буфер — як описано вище, без нового запису в історії). Зараз ⌘K має лише текстові дії, тож для картинок потрібен свій перелік дій.
- HEIC / TIFF у буфері стискаються так само (ImageIO читає їх).

## Дизайн: дрібніше

- **Зменшення в редакторі:** клавіша `-` зменшує картинку на 25 % (до 10 % оригіналу), ⌘Z повертає. **Конфлікт:** у редакторі цифри 1–9 уже вибирають інструменти (`AnnotationTool.key`), тож готові розміри на голі цифри, як у Clop, не поставиш. Тому (погоджено власником 2026-11-25) готові розміри — у меню кнопки зменшення: довша сторона 1920 / 1440 / 1280 / 1024 / 800 / 640, без цифрових клавіш.
- **Обрізання під пропорції:** наявний інструмент обрізання (`c`) отримує вибір пропорції: вільна / 16:9 / 1:1 / 4:5 / 9:16. Тільки для картинок. Обрізання кадру відео в 0.5.0 не робимо (*моє рішення*: для бага область уже вибрана під час запису).
- **Дії для Shortcuts (App Intents), у 0.5.0 (погоджено власником 2026-11-25):** «Стиснути картинку під N» (файл чи картинка на вхід, JPEG на вихід) і «Зробити знімок області». Запис через Shortcuts не робимо: він потребує вибору області руками.

## Що лишається будівельнику

Розкладка вікна запису, вигляд рамки і кнопки «Стоп», тексти й переклади (EN + UK), розбиття на файли в `AppFeature` / `CaptureKit`, тести на розрахунок бітрейту «під N МБ» і на стискання у фоні. Також ADR у `ARCHITECTURE_DECISIONS.md` для запису (вибір `SCRecordingOutput`) і запис у `CHANGELOG.md`. Сайт і гайд оновлює гілка «Сайт».
